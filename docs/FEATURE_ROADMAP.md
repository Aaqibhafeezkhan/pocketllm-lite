[`COMPETITOR_RESEARCH.md`](COMPETITOR_RESEARCH.md). Scores are judgments, not
measurements: Impact and Effort are 1 (low) to 5 (high); Risk covers privacy and
maintenance. Items marked "blocked" need something this environment did not have.

## 30 days (stabilize and be installable)

- Items 1, 2, 4, 5, 8, 9 (all small, mostly independent).
- Fix the 7 ESLint react-hooks errors and make lint blocking (O10).
- Publish `DEVELOPMENT.md` (done in this pass) and the contributor path and open the first
  labelled issues (see `CONTRIBUTOR_GROWTH.md`).
- Start the weekly `scripts/growth_report.mjs` snapshot.
- Exit criteria: `releases/latest` yields an APK with a checksum; CI green on
  Flutter and web; README screenshots match the shipped UI.

## 60 days (prove it works on real hardware)

- Items 3, 6, 7, 11, 14.
- Run the manual matrix in `QA_TEST_REPORT.md` section 5 on at least three
  devices (low, mid, high RAM) and record results in the repo.
- Exit criteria: a published matrix listing device, model, quantization, load
  time, tokens/second and failures. Each cell is measured or marked untested.

## 90 days (differentiate)

- Items 10, 12, 13.
- Decide, with data, whether to add a second mobile backend.
- Evaluate multimodal and voice-conversation work only if the matrix and
  accessibility pass show headroom. Do not start them before then.
- Exit criteria: a written go/no-go on the backend contingency with measured
  evidence, and a retrieval evaluation that runs in CI.

## Explicitly not planned

Hosted inference, accounts or sync, ads or analytics SDKs, a user-generated
persona marketplace, automatic task-based model routing, and unverified
"supported model" lists.
